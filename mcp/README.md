# The Mosaic HR MCP server

Nine tools, three transports, one factory. Everything real lives in `src/hrmosaic/mcpserver/`; this
directory holds the standalone entrypoint, the two run scripts, the generated tool schemas and this
note.

> **⚠ This directory deliberately has no `__init__.py`.** The requirement asks for a top-level
> `mcp/` directory and the SDK is also called `mcp`. Without an `__init__.py` this directory is never
> a regular package, and a namespace portion never wins over a regular package found later on
> `sys.path` — so `import mcp` still resolves to the installed SDK even with the repository root on
> the path, which is exactly the situation under pytest. Two tests hold the line:
> `tests/architecture/test_conventions.py::test_mcp_dir_is_not_a_package` asserts the file's absence,
> and `tests/contract/test_mcp_api_shape.py` imports `mcp.server.mcpserver` from the repository root
> and checks the module it got came from `site-packages`.

## Files

| Path | What it is |
|---|---|
| `server_entrypoint.py` | `--stdio` (default) or `--http --port N`. Argument parsing only. |
| `run_stdio.sh` | `python mcp/server_entrypoint.py --stdio` from the repository root. |
| `run_http.sh` | The standalone HTTP form, for pointing MCP Inspector at a server with no web app in front of it. |
| `tools/*.schema.json` | Generated by `python scripts/gen_tool_schemas.py` from a live `tools/list`, and committed. `tests/contract/test_tool_schemas_committed.py` asserts they still match. |

## Transports, and why there are three

One `build_hr_server(deps) -> MCPServer` factory serves all three. Nothing in a tool knows which
transport carried the call.

| Mode | `MCP_TRANSPORT` | Where it is used | Endpoint |
|---|---|---|---|
| **Streamable HTTP, mounted in-process** | `http` (default) | the deployed service — the graded topology | `http://127.0.0.1:${PORT}/mcp-server/mcp`; externally reachable only from a `Host` on `MCP_ALLOWED_HOSTS` — see *Native `Host` / `Origin` allowlist* below |
| **stdio subprocess** | `stdio` | local dev, the demo video (a visibly separate OS process), the fast CI discovery test | `python mcp/server_entrypoint.py --stdio` |
| **Remote Streamable HTTP** | `http` + `MCP_SERVER_URL` | R7.3 — the same client against an external endpoint; CI tests it against a second local uvicorn on another port | any external MCP endpoint |

**Why mounted in-process is the default.** The deployment is one 0.1-CPU Render instance. A second
process would double the resident set for no architectural gain, and a loopback HTTP hop inside one
process still exercises the whole MCP protocol — `initialize`, `tools/list`, `tools/call`, session
ids, SSE framing — so the graded topology is a real MCP client talking to a real MCP server.

**What that costs, and how it is paid.** The MCP server shares its event loop with FastAPI. A
synchronous SQLite read or an ONNX embed on that loop would stall `/chat`, `/health` and the SSE rail
at the same time. So **every tool handler is `async def` and every CPU-bound call is inside
`await asyncio.to_thread(...)`**. That is the rule the whole topology rests on.

**Why stdio still exists.** It is the demo's evidence that this is a real MCP server and not a
function call wearing a costume: the video shows a separate OS process, and CI's discovery test
spawns one with no port and no uvicorn.

## Discovery flow

1. `initialize` → `InitializeResult{protocol_version, server_info{name: "mosaic-hr", version}}`.
2. `tools/list` → per tool `{name, description, input_schema, output_schema, annotations}`. The
   client validates each input schema is a well-formed JSON Schema object and sorts the catalog
   deterministically, which keeps the prompt prefix stable for caching.
   `get_policy_section` is the one tool whose published `input_schema` carries a root
   `oneOf` — spec §8.4 requires its exactly-one-selector rule *in the schema*, and `@server.tool`
   derives the schema from the handler signature with no override hook, so `build_hr_server()`
   amends that one registered tool after registration
   (`tools/get_policy_section.publish_selector_one_of`). It is a **publication** only: the SDK still
   validates arguments against the signature-derived model, and the selector rule is enforced in the
   handler. The Anthropic Messages API rejects a root combinator, and that is handled on the wire by
   `AnthropicAdapter`, which strips `oneOf` / `allOf` / `anyOf` from the top level of what it sends
   and never rewrites what the server publishes (`core/llm/base.py::ToolSchema`).
3. **Exactly one `mcp_discovery` span per turn.** The handshake is cached per process (re-run on
   first use or after a failure); the *span* is emitted every turn, carrying the cached catalog plus
   `{cached, handshake_ms, discovered_at, catalog_sha, tool_count, mcp_session_id}`. Without that,
   only the first turn after a boot would carry the primary RUBRIC5.2 evidence.
4. Per turn the catalog is converted to OpenAI-shaped function schemas — **the array handed to the
   model is that conversion**, never a hard-coded list.
5. `tools/call` carries `_meta` (below). Results are read from `structured_content` when present,
   falling back to `json.loads(content[0].text)`.

## `_meta` conventions

Every `tools/call` carries three keys. They are namespaced with a slash so they can never collide
with the SDK's own reserved `io.modelcontextprotocol/*` keys, and the SDK round-trips unknown `_meta`
keys verbatim.

```jsonc
"_meta": {
  "mosaic/trace":     {"trace_id": "<session id>", "turn_id": "…", "parent_span_id": "…"},
  "mosaic/actor":     {"employee_id": "E1042", "source": "explicit"},   // explicit | default
  "mosaic/retrieval": {"strategy": "hybrid_rrf", "k_override": 5}       // nulls when unset
}
```

* **`mosaic/actor` is audit only.** The server echoes it so the client can record
  `actor_employee_id` / `actor_source` on the `tool_call` span and the dashboard can answer *who
  asked for this?* It gates nothing: the data is synthetic and the rubric asks for no authorization
  model. When the key is absent the server reports `source: "default"` and `employee_id: "E1042"`.
* **`mosaic/retrieval` is how `/chat`'s options reach the retriever.** Retrieval lives inside the MCP
  server and `agent/**` may not import it, so a `tools/call` is the only path. Precedence inside
  `search_policy_documents` is `k_override → the model's k → RETRIEVAL_K`, with `k_override` clamped
  to `1 ≤ k ≤ 10`, and the resulting `k_source ∈ {override, model, default}` is recorded on the
  `retrieval` span. `strategy` is validated against `{hybrid_rrf, dense_only}` **at the tool
  boundary**, because `retrieve()` treats anything that is not `dense_only` as hybrid and a typo
  would otherwise be retrieved as hybrid and audited as a typo.

## `_trace` on the result

The server never writes a span: `core/trace.py` is the only writer in the project, and over stdio
there is no turn to write into. Instead a tool returns the spans it produced under a `_trace` key
inside its result body, and the client lifts them and re-parents them under its own `tool_call` span,
so the audit trail stays complete even if the MCP server is split into its own service.

```jsonc
"_trace": {
  "spans": [{"span_id": "…", "kind": "retrieval", "name": "search_policy_documents",
             "started_at": 1_760_000_000_000_000, "ended_at": …, "duration_ms": 12,
             "status": "ok", "payload": { /* the §10.2 retrieval payload */ }}],
  "server_timing_ms": 12,
  "actor": {"employee_id": "E1042", "source": "explicit"},
  "server": "mosaic-hr",
  "transport": "http"
}
```

`_trace` lives **inside the result body** rather than in the result's `_meta`, so it survives both
read paths of the discovery flow's step 5 — a client reading `structured_content` and a client
reading `json.loads(content[0].text)` both get it. The published `output_schema` does not list it;
JSON Schema admits additional properties by default and the SDK's output validation ignores extras,
so the schema stays a description of the tool's own contract.

`server_timing_ms` and `actor` ride in the same envelope because the client's `tool_call` payload
declares both (§10.2) and a second sibling key would be one more thing for a client to know about.

## Error semantics

| Situation | What the client sees |
|---|---|
| Schema violation | `isError: true` with the validator's message as text — see the measured note below |
| Domain "not found" | a **successful** result: `{"status": "not_found", "code": "EMPLOYEE_NOT_FOUND", "hint": "Employee ids look like E1042."}` |
| Bad selector on `get_policy_section` | `isError: true`, `{"code": "INVALID_ARGUMENTS", "fields": ["heading_path", "chunk_id"]}` |
| Write tool without a valid token | `isError: true`, exactly `{"status", "code", "action", "human_summary", "arguments_preview"}` — **and no token of any kind** |
| Transport failure | the client retries once, emits an `error` span, `/health` flips `mcp.connected = false`, and the turn degrades to a policy-only answer at HTTP 200 |

## The confirmation gate is a wire-level check

`create_mock_hr_ticket` and `draft_hr_email` compare the **raw arguments of the request** — not the
validated ones the handler receives — against `confirmations.arguments_json`, using
`confirm.canonical_arguments()` (sorted keys, tight separators, `confirmation_token` excluded). The
handler sees schema defaults already applied, so comparing those would let a caller who omitted
`priority` mismatch a token minted from the arguments the client actually sent.

Two consequences worth knowing:

* `web/` must mint from the **exact** arguments recorded on the gated attempt's `tool_call` span
  (§8.6 step 3), never from `arguments_preview`, which is a display subset.
* The SDK's in-process shortcut `server.call_tool(name, args)` carries no request at all, so the gate
  always rejects there. That is the fail-safe direction, and it is why every gate test goes over a
  real session.

## `mcp` 1.x → 2.x, in full

This project is written against **`mcp==2.2.0`**. Everything below was checked against the installed
package on 2026-09-09, and `tests/contract/test_mcp_api_shape.py` pins the four that fail silently.

| Subject | 1.x | 2.x (what this repo uses) | How it fails if you get it wrong |
|---|---|---|---|
| Server class | `from mcp.server.fastmcp import FastMCP` | `from mcp.server.mcpserver import MCPServer` | `ModuleNotFoundError` — 2.2.0 ships a stub `mcp/server/fastmcp.py` whose only job is to raise with the migration URL |
| Streamable HTTP client | `streamablehttp_client` | `streamable_http_client` | `ImportError` |
| Client yield arity | `(read, write, get_session_id)` — 3-tuple | `(read, write)` — 2-tuple | `ValueError: too many values to unpack` at connect time |
| Result field names | camelCase attributes (`serverInfo`, `inputSchema`, `structuredContent`) | snake_case attributes (`server_info`, `input_schema`, `structured_content`); the **wire** is still camelCase via a `to_camel` alias generator | `AttributeError`, or worse, `getattr(..., "inputSchema", None)` silently returning `None` |
| Wire types package | `mcp.types` | `mcp_types` (a standalone package; `mcp.types` still mirrors it name-for-name) | nothing — both work, but `mcp_types` is the one with no transport dependencies |
| Tool annotations | `ToolAnnotations(readOnlyHint=…)` | `ToolAnnotations(read_only_hint=…, destructive_hint=…, idempotent_hint=…, open_world_hint=…)` | pydantic accepts both spellings (`populate_by_name`), so a wrong guess is silently accepted — but only the snake_case name exists as an attribute |
| Per-request context | a context variable on the low-level `Server` | a `Context` parameter injected by type annotation; `ctx.request_context.meta` / `.params` | `_meta` silently unavailable |
| In-process test client | `mcp.shared.memory.create_connected_server_and_client_session` | `mcp.Client(server)` (or `mcp.client._memory.InMemoryTransport`) | `AttributeError` |
| Tool result | return a value, or `list[TextContent]` | return a value **or** a `CallToolResult` directly, which is how a tool sets `is_error` **with** `structured_content` | an error payload arrives as plain text with no structured content |
| Mounting | `FastMCP.streamable_http_app()` + `session_manager.run()` in the lifespan | unchanged in shape: `MCPServer.streamable_http_app()`, then `async with server.session_manager.run()` | `RuntimeError: ... can only be called once per instance` if the manager is reused |

### Two things measured here rather than assumed

* **`structured_content` is populated on *both* transports in 2.2.0.** An earlier probe recorded it
  as `None` over stdio, and the design (§8.2 step 5) therefore requires a client to fall back to
  `json.loads(content[0].text)`. Measured on 2026-09-09 against this server, both transports return
  it — because every tool here returns an explicit `CallToolResult` carrying both. The fallback path
  stays, and `tests/integration/test_mcp_tool_call.py` asserts the two paths agree, so a client
  written against either is correct.
* **A schema violation is `isError: true` with a text message, not a JSON-RPC `-32602`.** Design
  §8.3 describes it as "`isError: true` with JSON-RPC `-32602`"; in 2.2.0 the validation failure is
  caught by `MCPServer._handle_call_tool` and returned as
  `CallToolResult(content=[TextContent(...)], is_error=True)` — the `-32602` code never reaches the
  wire. The behaviour the orchestrator depends on (one repair round-trip, then degrade) is
  unchanged, since it keys on `is_error`.

## Native `Host` / `Origin` allowlist: what the SDK grep found

The design promised to check whether `mcp` 2.2.0 offers a native DNS-rebinding control before writing
any MCP code, because *a control claimed in a design doc but absent from the SDK is worse than none*.

**It does.** `mcp/server/transport_security.py` defines `TransportSecuritySettings` with
`enable_dns_rebinding_protection`, `allowed_hosts` and `allowed_origins` (exact matches plus a
`host:*` wildcard-port form), applied by `TransportSecurityMiddleware`, and both
`MCPServer.streamable_http_app(...)` and `run_streamable_http_async(...)` accept a
`transport_security=` argument.

**Passing nothing is not "no allowlist".** This paragraph used to say it was, and that was wrong.
`TransportSecurityMiddleware(None)` does construct
`TransportSecuritySettings(enable_dns_rebinding_protection=False)` — but a mounted server never
constructs the middleware itself. `streamable_http_app()` does, and it fills in a **loopback
allowlist** first whenever its `host` argument is `127.0.0.1`, `localhost` or `::1`
(`mcp/server/lowlevel/server.py:742-746`) — and `host` **defaults to `127.0.0.1`**. So
`server.streamable_http_app()` with no arguments, mounted at `/mcp-server`, enables protection with
`allowed_hosts = ["127.0.0.1:*", "localhost:*", "[::1]:*"]`, and every request arriving with a
public `Host` header gets `421 Invalid Host header`. That is what the deployed endpoint did until
P23, and it is why an MCP Inspector session against
`https://mosaic-hr-copilot.onrender.com/mcp-server/mcp` failed with a bearer token that was
perfectly valid. It is fixed: see *Status on the live service* below.

**So the allowlist is configured, and protection stays on.** `mcpserver/asgi.py` builds a
`TransportSecuritySettings(enable_dns_rebinding_protection=True, allowed_hosts=…,
allowed_origins=…)` from the `MCP_ALLOWED_HOSTS` setting — default `127.0.0.1:*,localhost:*`, with
`render.yaml` adding `mosaic-hr-copilot.onrender.com` for the deployment — and passes it to
`streamable_http_app(transport_security=…)`. `allowed_origins` is derived from the same list as
`http://<host>` and `https://<host>`. A `Host` outside the list still gets a 421: that is the
control working, not a fault. `tests/contract/test_mcp_host_allowlist.py` drives real `initialize`
requests through the mount and asserts all three cases — the public hostname accepted, an unlisted
one refused, and loopback unchanged.

**The allowlist is the second control, not the only one.** The mount is also behind the FastAPI
access gate (`APP_ACCESS_TOKEN`, P8) and the per-IP rate limit, and the two state-changing tools
need a one-time confirmation token an external caller cannot obtain.

**Status on the live service, verified 2026-09-11 at 20:32Z: the public mount accepts external MCP
clients.** The running instance had been created over the REST API before `MCP_ALLOWED_HOSTS`
existed; the variable is now set on the service — the same
`127.0.0.1:*,localhost:*,mosaic-hr-copilot.onrender.com` the committed `render.yaml` carries — and
an external `initialize` sent over the
public hostname answered **HTTP 200**. A full external client session then listed all **nine**
tools and ran `search_policy_documents` and `check_pto_balance`; a `create_mock_hr_ticket` call
with no confirmation token was refused with `CONFIRMATION_REQUIRED`, and so was the same call
carrying a forged token; a request without the bearer header got **401**. So an MCP Inspector
session attaches to `https://mosaic-hr-copilot.onrender.com/mcp-server/mcp` with
`Authorization: Bearer $APP_ACCESS_TOKEN` as a custom header. **The other two ways to see the same
nine tools from the same factory are unchanged: the stdio entrypoint (`mcp/run_stdio.sh`) and
`/dashboard/mcp`.**
