{# The shared table partial (§11.6). Wide tables scroll inside their own container, never the page. `columns` is a list of dicts: {label, key, kind, cls?, help?, href_prefix?, href_suffix?, link_key?, n_key?, unit?, detail_key?} `rows` are the plain dicts of the view-model — the very dict the matching `/api/*` route returns — so the table and the Export JSON link can never disagree. **The rules applied here once, and inherited by all ~20 tables (UX W4, plan §3.10).** * Lead with the human column; ids move to the end as `kind: 'id'`, an 8-character chip carrying the full value in `title=` and still linking to it. 32-hex ids were the first and widest columns — 575px of 1238 on Turns — hiding the one column a reader came for (`dashboard-readability-11`, `numbers-precision-overflow-10`). * Every numeric kind is right-aligned with tabular figures, and the header carries the same `cell-{kind}` class so the label sits over its values (`numbers-precision-overflow-9`). * Every cell carries `data-label`, which is what the stacked card layout under 640px prints as its row heading; `data-col` is unchanged, because the contract tests select on it. * `help` puts a dotted-underline definition on a header for the terms a grader cannot be expected to know (`dashboard-readability-5` — the owner ruled out a glossary page). * Multi-value cells separate their pills, so copied or announced text is `clarify, error` and not `clarifyerror` (`dashboard-readability-30`). * `detail_key` renders a second, full-width row holding whatever the summary cell summarised — the raw JSON a one-line human summary replaced (`dashboard-readability-19`). * `zero_dash` is for a column where zero means *did not happen* — a rate-limit wait, a retry count. `<1 ms` on every row of a column nothing ever used is noise, not a measurement.
