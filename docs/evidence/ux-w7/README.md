# UX W7 — before and after, for the Critical and each dashboard regression

Eight pairs, sixteen files. Each pair is the same screen id at the same viewport.

* **before** — the second re-audit's own capture set, the screens its auditors judged on
  2026-09-15 (`make ux-capture` on `d8a2ca3`, LOCAL, `LLM_PROVIDER=stub`). Those screens were taken
  by *resizing* one loaded page, which is what the phone half of them photographs.
* **after** — `make ux-capture` on this wave's head, same harness, same four scripted servers, same
  stub scripts — and since this wave every viewport is a **fresh load** of the page, never a
  resize. No live model call was made and `.env` was never read.

| Finding | before → after | what changed |
|---|---|---|
| **cpux2-1 = a11y-re2-2 (Critical)** — on a phone the newest turn was never brought into view and *Jump to latest* was dead: every scroll mechanism wrote to a box that no longer scrolled | `chat-answer-390-before.png` → `chat-answer-390-after.png` | the document is the scroller below 30rem; after the turn lands the page is scrolled to the end of the answer, and the button rides the viewport above the composer when the reader scrolls up |
| **dgc-r2-3** — the in-flight screen was the question echoed over ~400px of empty ground | `chat-inflight-390-before.png` → `chat-inflight-390-after.png` | the assistant's bubble and *"Working on it…"* exist from the moment the question is sent |
| **npo3-01 = DR2-08 = JX2-06, DR2-01** — the Runs table's RUN column shredded the label mid-word and spelled the variant two ways beside itself; the headline table lost its date to a hover | `dashboard-evals-1280-before.png` → `dashboard-evals-1280-after.png` | one run label, built once through `enum_label`, on one line; a painted Created column first in the headline table |
| **npo3-02** — the retrieval QUERY column was a 55px ribbon of word fragments beside 200px of empty STRATEGY | `dashboard-retrieval-1280-before.png` → `dashboard-retrieval-1280-after.png` | prose columns keep a 10rem measure and break between words; a badge column takes no width it does not need |
| **DR2-02** — every span emitted a full-width payload row: 28 spans, 56 rows, 7,619px on a phone | `dashboard-session-390-before.png` → `dashboard-session-390-after.png` | the disclosure is a seventh-column chevron and a closed payload costs no row; on a phone each step is two lines; 4,800px |
| **nav-r2-2 = nav-r2-3** — three bare buttons with no roles, two thirds of the page `hidden`, the tab not in the URL | `dashboard-eval-run-1440-before.png` → `dashboard-eval-run-1440-after.png` | a real tablist driven by `?tab=`; the run page's filters live inside the Items panel |
| **Addendum 2 (owner)** — the group labels sat in the same row and weight as the page links | `zoom-dash-nav-390-before.png` → `zoom-dash-nav-390-after.png` | eyebrows and pills; the current item centred in the row on a phone (nav-r2-4) |
| **Addendum 2 (owner)** — the panel shipped as a collapsed disclosure that remembered an open | `demo-panel-1440-before.png` → `demo-panel-1440-after.png` | a plain always-expanded section, every control on the page; the persona picker first (M12), the session id chip (M17) |

The full set of 70 screen ids × 3 viewports is regenerated by `make ux-capture` into the
git-ignored `.ux-capture/`; only the sixteen files above are committed.

Three screens in that set — the confirmation card and its two zooms — are the one documented
exception to the fresh-load rule: a replayed conversation never offers a confirmation it cannot
honour, and the stub script cannot produce the card twice, so they are taken on the live page by
resizing it and their `state` in `index.json` says so.
