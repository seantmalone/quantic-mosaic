## Task 1b — Clarification: infer the slot order when the router names no workflow

Closes the remaining half of gap **4** (clarification accuracy 0.667 on the shipped build).

Evidence (deployed run `r_1790062696_baseline`, item `amb-002`, question *"Am I allowed to work from there for a while?"*, persona E1042): the router returned `intent: policy_qa`, `workflow: null`, `needs_clarification: true`, `rationale_summary: "Remote work eligibility requires location: 'there' is unspecified. Clarify the destination country or city."` Because `workflow` was null, `unfilled_slots()` in `src/hrmosaic/agent/orchestrator.py` found no slot order (`CLARIFY_SLOT_ORDER` is keyed on workflow; `CLARIFY_INTENT_ORDER` has no `policy_qa` entry), and the fallback path read `RATIONALE_SLOT_WORDS` from the rationale, which named only `destination_country`. The served question was *"Happy to check — where would you be working from?"* The dataset's `clarification_expects` for amb-002 is "the destination country and the start and end dates", and the judge's `named_missing_information` was false.

1. When the router asks for clarification with `workflow: null`, infer the workflow from topic words in the rationale and the user's question before falling back to the rationale slot words: a small `CLARIFY_TOPIC_WORDS` table mapping e.g. ("remote work", "work from", "working from", "abroad", "another country", "another state") → `remote_work_eligibility`; ("time off", "pto", "leave", "vacation", "days off") → `pto_request`; ("expense", "reimburse", "claim") → `expense_claim`. Read as data only (which closed workflow it names), never as an instruction. Then use `CLARIFY_SLOT_ORDER[workflow]` with the session's `known` slots and `has_record`, so amb-002 asks for the destination *and* names "how long you would be there, and from when".
2. Keep the existing rationale-word path as the fallback when no topic matches.
